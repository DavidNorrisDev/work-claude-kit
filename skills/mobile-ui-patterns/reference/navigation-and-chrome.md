# Navigation and chrome

## 5. Navigation and contextual chrome

- A floating tab bar suits a small set of destinations: five is the ceiling, three or four is better. Break the primary action out (e.g. a prominent add button) rather than burying it.
- When destinations don't reduce to a few icons, promote the "sidebar" to a browsable home screen instead of forcing a tab bar.
- Chrome is contextual. Tab bars and top-bar actions change per screen. Entering a detail/editor can hide the tab bar and reveal actions specific to that context (formatting, share), then restore on exit.
- **Check:** are top/bottom actions the *right ones for this screen*, or generic leftovers from elsewhere?

## 6. Keep the user in context — sheets over page-pushes

For a sub-task that belongs to the current screen (picking a template while editing, choosing options), use a bottom sheet rather than pushing to a whole new page. It keeps the user in place and is gesture-navigable.

- Reserve full-screen navigation for genuinely separate destinations.
- **Check:** does this sub-task tear the user away from what they were doing? If it's a child of the current task, make it a sheet.
